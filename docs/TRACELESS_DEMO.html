TRACELESS

See what a stalker’s AI sees in your photo — then make it unplaceable.
Technical & demo document · Built by a Claude Code builder lane, committed by Devin · Every number in this document was measured by the system or its benchmark scripts.

1 · The Problem

In 2019, a man in Japan found a pop idol’s home from the reflection in her eyes in a photo she posted. In 2025, AI “geoguessing” went viral — tools like GeoSpy place a photo in seconds. Every social app strips EXIF location data. Nobody strips the picture. The pixels themselves are the leak: sign text, vegetation, architecture, road markings, and reflections carry location whether metadata exists or not.

Defenses exist mainly in research papers. We checked the product landscape and found no shipping product that detects the visual clues, removes them, and proves the removal worked. TRACELESS is that loop, end to end, on one laptop.

One-liner: Upload a photo. Watch five different AIs place it. Watch the clues get erased. Watch the same AIs fail. Get the photo back on your phone, safe to post.

2 · What TRACELESS Does

  1. Clue zero. Reads EXIF/GPS, shows it, strips it before any attacker sees the image. GPS is never attack input — it is only the answer key for measuring error.
  2. The attack. Five independent geolocation models attack the pixels in parallel. Numbered clue boxes (OCR text, segmentation, faces/reflections) are found and merged with attacker-reported clues.
  3. Clue accounting. Each clue’s contribution is measured by ablation: erase only that clue, re-attack, record the change in 90% credible area and top-1 error.
  4. The defense. Least-destructive fix per clue: LaMa inpainting, glyph-level text erasure, blur, reflection softening. Faces are never altered except softening eye reflections.
  5. Proof. Re-attack with all attackers — including an adaptive attacker told the photo was edited. “Safe” means every tested attacker misses by more than the chosen radius (default 25 km). If it cannot be reached, we say so.
  6. Handback. QR code → the judge downloads the protected photo to their own phone.

5 · Truth Rules (enforced in code)

EXIF/GPS is stripped before any attacker sees pixels; GPS is only an answer key.
Eye reflections are claimed readable only above a measured iris-pixel threshold; below it, reflective surfaces are flagged as “possible clue” and softened as a labeled precaution.
Every on-screen number comes from the run or the benchmark scripts. Clue contributions are measured by ablation, never invented.
“Can’t be placed” means “not within the chosen radius, by the attackers we tested” — stated with both.
Street-level claims only inside downloaded coverage; coverage size is always shown.
No “locate any photo” mode. The attack is a risk report on your own photo. Exact coordinates only for public landmarks or with the owner’s OK.
The person is never altered, except softening eye reflections. Photos stay on the laptop; wipe deletes them.

7 · Built with Devin (the workflow itself)

This repo ran a split-brain agent workflow: Claude Code was the builder — architecting, writing, and self-verifying all code across multiple autonomous sessions — while Devin was the orchestrator and committer: issuing the brief and upgrade specs, reviewing every diff, and authoring all 12 commits on github.com/Anandb71/traceless. The builder logged 20+ design decisions in DECISIONS.md and answered the upgrade spec with UPGRADE_PLAN.md before touching code.

  • Headless claude -p sessions with streamed JSON logs watched for DEVIN_COMMIT_READY markers; Devin committed each verified unit.
  • Session continuity via --continue: the builder kept full context across build → upgrade → freeze → final pass.
  • Self-verification: visual QA via self-screenshots, golden tests, a 5-photo rehearsal script, measured thresholds — not vibes.
